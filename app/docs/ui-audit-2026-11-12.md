# UI audit, 2026-11-12

This follows the accepted application shape and staging fixes at `191f34f`.
It changes the page, its tests and documentation. The broker interface and
deployment are unchanged.

## Changes

- All displayed wall-clock times and dates use `public/time.js`. Its default
  is the browser's locale and zone, including the locale's preferred hour
  cycle. There is no app setting, fixed locale, fixed zone or forced 12/24-hour
  choice. Short clocks use the locale's `timeStyle: short`.
- Files and Appearance use the same `segmentedControl()` builder. Buttons
  retain enough width for their labels, with shared selected, hover and
  keyboard-focus states.
- Markdown file headings omit `.md`/`.markdown`, case-insensitively. Stored
  names, paths, list rows, type chips and creation fields retain the filename.
  Size and age remain below the display heading.
- Document H1–H4 use 36, 28.8, 24 and 20.4px at the default size, derived
  from `--type-title`. Messages use 27.6, 24, 20.4 and 16px. Heading margins
  are 1.25em above and .45em below; the first heading has no leading gap.
- Activity's working title clamps to two lines. Jobs show the asking agent's
  face, with a project mark when no asking agent is in the roster.
- The thread header title fills the available width up to its actions.
- Standalone buttons and form controls have a shared 44px minimum. Scoped
  smaller minima in Files, Activity, profiles and schedules were corrected.
  Board grip/check/menu columns now accommodate their targets. Editable
  Markdown tasks keep a 17px check mark inside a 44px input; disabled transcript
  checks keep their compact presentation. Schedule switches keep a 28px track
  inside their 44px hit area.
- Form placeholders use the readable quiet-ink token. Copy controls keep full
  opacity on touch screens, with room above code and tables for the larger
  target. Filled Files controls have a distinct hover surface. Shared keyboard
  outlines cover plain text actions and fields as well as icon buttons.
- Combined Settings sections retain the shared 14px vertical gap between
  their children. Voice's cards no longer touch, and section kickers have no
  competing browser margin.
- The attachment picker and phone provider page no longer draw a second
  heading/close control above their own chrome. Files sheets reuse the shared
  sheet handle and dismissal gesture.

## Display-format inventory

| File / caller | Display |
| --- | --- |
| `sessions.js` / `when()` | Thread-list clocks, weekdays and older dates |
| `thread-experience.js` / `replyTimestamp()` | Message footer and full-date tooltip; local calendar-day grouping |
| `activity.js` / `activityTime()`, `activityDay()`, thread history row | Event ranges, day headings and trailing thread clocks |
| `files.js` / `age()` through `metaOf()` | Older file dates; relative ages retain their existing words |
| `providers.js` / `dayMonth()`, `resetWord()` | Sign-in expiry and quota reset dates/clocks |
| `integrations.js` / `dateWords()` | GitHub authorization and plugin token expiry dates |
| `schedules.js` / `dateWords()` | The next scheduled fire, in the browser's zone; the old hard-coded PT suffix is gone |
| `threads.js` / thread row tooltip, task panel | Full activity and task timestamps |
| `threads.js` / board item deadline | A stored calendar day |
| `apps.js` / expiry or shared-until | Calendar dates or timestamp dates |

Date-only values such as `2026-11-12` name a calendar day. The helper renders
those in UTC so a deadline does not move to the preceding day in western zones.
A value with a time is an instant and follows the browser's zone. This distinction
is tested, including a timestamp crossing midnight.

These are deliberately outside wall-clock formatting: relative ages and
durations, dictation/playback elapsed clocks, ISO serialization, board deadline
arithmetic, Files' daily/inbox filenames and date fields in stored records.
Authored schedule expressions and the schedule-input grammar still say PT:
that is the host's scheduling language, rather than a formatted next-fire instant.
A source guard rejects additional `Intl.DateTimeFormat`, `toLocale*String`,
`hour12` or `hourCycle` formatters in other public modules.

## Browser evidence

[Screenshots and results](evidence/ui-audit-2026-11-12/README.md) come from the
real page and relay against synthetic host answers, using Chromium. The matrix
is 390×844 and 1440×1000, Latte light/dark and Plain light, at app size 100%.
It starts no coding session and uses no provider credential or production data.

The driver visits chats and search, long Markdown conversations and permissions,
new-thread/configuration and branch sheets, composer menus and expanded editor,
boards and their editor, Files roots/folders/actions/viewers/editor/picker,
read-aloud controls, Activity, profiles/schedules, every Settings section and
Apps. It also visits empty and failure states, including read/save failures,
sign-in, microphone/terms and audio failures. Files media include image, broken
image, PDF, download-only and HTML/source views. Apps use a framed fixture on
desktop and the existing browser-opening journey on phones.

Every capture checks document overflow, visible enabled control sizes, text and
placeholder contrast against composed backgrounds, and keyboard focus. Desktop
checks exercise hover on Files, Apps and Appearance controls. A counterfactual
restores the compact footer size and must be caught by the target-size guard.
The checks account for text opacity and exclude disabled controls and invisible
content. They measure the app's DOM, not native PDF UI or another app's iframe.
Browser/OS permission dialogs and actual provider approval remain outside this
fixture. The ordinary suite exercises the account state machines and relay.
The optional native-Chromium layout harness now waits for the fixture URL's
completed navigation before evaluating it: a fast browser could otherwise run
against `about:blank` and lose its execution context during navigation.

Four additional real-browser contexts compare the list, footer, Activity and
schedule clock against the browser's own formatter: en-US/en-GB, each in
America/Los_Angeles and Asia/Tokyo. Unit tests also cover DST, a locale hour-cycle
extension, absent dates and non-Latin calendar-day grouping.

## Removed debt

`public/sessions.js` now contains shared agent identity, token labels and list
timestamps. Its unused classic session-list state, listing/snapshot merge,
filter/search/count model, unread comparisons, row/bubble presentation, quiet
status ladder, imported-history cost estimate and resume-warning calculations
were removed. Their old-screen tests were removed; identity and time tests remain.

The unused `chat-bubbles.js` module and its retired preference accessors were
removed. `store.js` no longer offers classic draft/unsent or context-warning
accessors and normalizers. Existing stored draft content is left untouched.
Thread drafts continue through the thread controller.

The page lost the unused `openMine` alias, `dictationSummary()` and
`integrationsSummary()`. Shared UI lost `statusBox()`, `loadingCard()` and
`headBlob()`, plus the corresponding unused box/loading/avatar/bubble-preview
styles. Shared row, title, tag and thread positioning styles remain.

The Activity demo fixture lost its independent seen route, unread counter and
seen fields. Its tooling test now uses Schedule's own seen route; Schedule's
reading state remains a working capability.

The remaining System checks are reachable saved-link soft landings and relay
rejections, backed by regression tests. The numbered-colour aliases in
`readAvatarColours()` remain reachable configuration migration inputs: removing
them would break accepted configuration. Every produced CSS reference is
semantic. Protocol helpers still exercised by tools and tests remain.

## Main script and the next module split

`public/app.js` is **6,296 lines / 264,394 bytes** (258.2 KiB), down from
6,316 lines / 266,026 bytes at this audit's starting commit. No module/plugin
split is implemented in this change.

| Boundary | Ownership and constraints |
| --- | --- |
| Shell/platform | API/auth, store/theme, rendering scheduler, viewport/zoom, route/history and menu-surface ownership. Keep the pre-paint theme boot and the frame/timer redraw race here. |
| Composer | The one rich draft node, attachments/upload, mention integration, expanded editor, focus and draft save/restore. Threads currently inject callbacks into it. A plugin needs a draft/field ownership contract. |
| Dictation | Recorder/live recognizer, microphone/terms settings, take lifecycle and insertion into a draft or file. It needs explicit target/leave hooks and must share audio ownership with playback. |
| Speech/playback | Take lookup/generation, players, file reading sheet, voice sample, Media Session and object-URL cleanup. The singleton active player and generation guards need a shared service. |
| Files integration | Existing `files.js`/picker plus the app's field cache, embeds, link resolution, unsaved-leave guard and speech/dictation adapters. Register routes and guarded navigation together. |
| Accounts | Provider sign-in, GitHub and plugin-integration flows, their requests/refresh/cancel logic and Settings views. Sensitive fields and temporary account selection must die with their view. |
| Transcript details | Fold/tool/item renderers and turn facts supplied through `stepUI`. Preserve normalized protocol views, stable item keys and open/copy state. |
| Profiles/schedules | Agent detail, scoped Activity, schedule editing and links into Files. It needs roster/Activity/Files services and a lifecycle for timers. |
| Destination/settings registry | Apps, Activity and Threads already have controllers. They can register screens, routes, settings sections and start/suspend/dispose hooks through a shell context. |

The main obstacles are shared mutable `state`, initialization callbacks that
close over later controllers, direct cross-controller navigation, document-level
event handlers, cached/kept DOM nodes and singleton audio/recorder ownership.
Menus also own focus restoration and responsive placement. Moving functions
without those lifetime contracts would leave duplicate listeners, stale async
callbacks or two owners of the same draft/player. Start with the shell context
and lifecycle, then move one cohesive state owner at a time.
