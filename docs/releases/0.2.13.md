# Loam 0.2.13

A new install is as safe as a long-running one: a firewall, and history
kept from the first minute. An update from an older Loam was tried for
real, from 0.2.0 and from 0.2.6, and keeps everything that is yours.

## New

- **A firewall on your server.** Only SSH, 80 and 443 reach it from
  outside, so a test server an agent starts is never on the open web by
  accident. If your server already has a firewall (ufw, firewalld), Loam
  leaves it as it is. To open another port, add it to `firewall.open` in
  `/etc/loam/loam.toml` (for example `["22000/tcp"]`) and run
  `sudo /home/loam/loam/bin/gen-deploy` (the path of a standard install).
- **History from the first minute.** Your vault and your agents' files are
  committed on this server every 15 minutes, with nothing sent anywhere,
  so a change you regret can be got back. Before this, a new install made
  the history and never added to it. The installer now says so at the end
  and recommends the Git backup plugin for a copy off the server.

## Changed

- **Plain words about what agents can do.** Your agents, and any plugin
  you install, have full control of the server Loam runs on. The README and
  every plugin's install screen now say so, with the advice that goes with
  it: use a server you use for nothing else.
- **What every agent is told no longer describes anyone else's server**:
  the owner is "they", and the vault opens in Files or any Markdown editor.

## Fixed

- **An update from an older Loam** now starts the timers a newer release
  adds (the 15-minute history among them) and stops the ones a release
  took out (Remote Control's, retired in 0.2.12, kept running on an
  updated server until now).
- The conversations folder was protected under the first install's folder
  name, which a new vault does not have; the protection now uses this
  install's own name, and agents' transcripts land in it.
- Adding a passkey on a staging copy of the app opened the wrong sign-in
  page.
- A Git backup push left `git status` saying "ahead"; the local record of
  the remote now follows the push.
- Downloading a folder holding a file over 50 MiB, on an older engine,
  said "Download started" and then failed; the zip now leaves the file
  out and says so inside.
- A link to a file inside a plugin's repository (`.../tree/main/README.md`)
  installs the plugin that file belongs to.

## Also in 0.2.12, and not said there

0.2.12 carried more than its notes said. If you are coming from 0.2.11 or
earlier:

- **Git backup**, built in and off until you turn it on in Settings ›
  Plugins: your vault and your agents' files go to private repositories of
  yours (GitHub, GitLab, Codeberg or your own), with a key that reaches
  only those repositories.
- **Loam offers Git backup once, when you first sign in**; skipping it is
  remembered.
- **The AI tools stay at the versions Loam was tested with**: Claude Code
  and Codex move when Loam updates, not on their own each night.
- **Download a folder as one zip**, from Files.
- **Install a plugin from any GitHub link**: a repository, a release, a
  tag, or a folder inside it.
- **Remote Control is retired.** You talk to your agents in Loam's app.
- **A message to an agent is never lost or reordered**, even when it
  arrives while the agent is busy.
- **Agents' commits carry your name** when your GitHub account is
  connected.

## Updating

Update from Settings › About Loam, or type `loam update` in your server's
shell. Nothing to do by hand: the update raises the firewall (or leaves
yours alone), starts the 15-minute history, and takes out Remote Control's
leftovers. If something of yours listens on another port and must be
reached from outside, add it to `firewall.open` as above.
